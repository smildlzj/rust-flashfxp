# 文档编写指引

rust-flashfxp 的 AI 协作文档体系：`CLAUDE.md`（索引入口）+ `docs/`（分层详情），架构文档位于 `docs/architecture/`。任何人（含 AI）新增或修改文档前，先读本指引。

## 写作原则

1. **渐进式披露**：`CLAUDE.md` 只放高频必备信息（≤50 行），细节一律下沉 docs/；入口用"需要什么 → 读哪里"路由表。
2. **源码实证**：写入的事实（布局、命令、职责、调用关系）必须来自对源码/配置的分析；分析不到的不写，禁止猜测。
3. **只反映当前状态**：不写 CHANGELOG、版本历史、更新记录，不引用提交号 / issue / MR 链接，不写文档自身的迁移说明；文档始终描述 as-is。
4. **排除普通可见知识**：README 已有内容、语言/框架通用知识不写入；只写本项目特有的信息。
5. **单一权威源**：同一事实只在一处权威展开，其他位置留一行路由，禁止跨文档双写。
6. **中文编写**：正文中文，代码、命令、路径、标识符保留英文。

## 结构约定

- `CLAUDE.md` 章节固定：项目概要 / 布局约束 / 构建与测试 / 协作约束 / 深入文档 / 其他——不得改名、合并或省略（构建与测试无可收录命令时整节省略）。
- 架构域入口 `docs/architecture/README.md`：文档导航 + 参考资料 + 当前已确认约束。
- 专题文档结构：目的 → 规范或机制说明 → 命令或示例 → 关联文档，一篇聚焦一个主题。

## 长度与拆分

- 任何文档超过约 300 行（或单主题明显膨胀）必须按主题拆分，原位置留一行路由链接。
- `CLAUDE.md` 上限 50 行，超长内容下沉 docs/。

## 新增文档流程

1. 确定归属域：架构类 → `docs/architecture/`；规范/指南类 → `docs/`；计划类 → `docs/plans/`（日期命名；`docs/plans/` 不入 git）。
2. 按"结构约定"编写，遵守写作原则。
3. 同步更新 `CLAUDE.md` 路由表与（如属架构域）`docs/architecture/README.md` 导航，禁止悬空链接。
